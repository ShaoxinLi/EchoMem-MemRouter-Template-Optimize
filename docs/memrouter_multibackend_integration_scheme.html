MemRouter 多后端集成方案

MemRouter 与 OpenViking 集成 + 可扩展多后端架构

一、核心设计目标

目标说明
OpenViking 集成MemRouter 输出的 BackendQueryInstruction 可直接被 OpenViking 消费，高置信场景跳过 IntentAnalyzer
后端可扩展新增记忆后端只需注册 backend + 写模板 + 实现 adapter，不修改 MemRouter 核心代码
query_spec 多后端路由一个模板可携带多个后端的查询规格，MemRouter 根据命中路由只输出对应后端的指令
向后兼容OpenViking 现有 search()/find() API 不变；MemRouter 旧 consumer 忽略 query_instructions 即可

统一协议层

所有后端通过统一的 BackendQueryInstruction 协议与 MemRouter 交互。后端差异由各自的 MemoryBackendAdapter 消化，MemRouter 核心只负责路由决策 + 指令生成。

三、OpenViking 侧集成（最小改动）

3.1 当前 OpenViking 检索入口

# VikingFS (openviking/storage/viking_fs.py)

# Entry A: find() — 无 session，直接构造 TypedQuery → HierarchicalRetriever
async def find(self, query, target_uri="", limit=10, ...)
    typed_query = TypedQuery(query=query, context_type=..., intent="")
    return await HierarchicalRetriever.retrieve(typed_query, ...)

# Entry B: search() — 有 session，先走 IntentAnalyzer → TypedQueries → retriever
async def search(self, query, target_uri="", session_info=None, limit=10, ...)
    if session_summary or current_messages:
        query_plan = await IntentAnalyzer.analyze(...)  # VLM (~3K-15K tokens)
        typed_queries = query_plan.queries
    else:
        typed_queries = [TypedQuery(...)]
    return await asyncio.gather(*[retriever.retrieve(tq, ...) for tq in typed_queries])

3.2 新增 execute_instruction() API

# openviking/storage/viking_fs.py  — 新增方法

async def execute_instruction(
    self,
    instruction: Dict[str, Any],  # BackendQueryInstruction 的 JSON/dict 表示
    ctx: Optional[RequestContext] = None,
) -> FindResult:
    """Execute a MemRouter-generated BackendQueryInstruction directly.

    This bypasses IntentAnalyzer when skip_intent_analysis=true,
    going straight to HierarchicalRetriever with pre-constructed TypedQuery.
    """
    from openviking_cli.retrieve import ContextType, TypedQuery, FindResult
    from openviking.retrieve.hierarchical_retriever import HierarchicalRetriever

    # 1. 解析 instruction 字段
    query_text = instruction["query"]
    target_uri = instruction.get("target_uri", "")
    context_type_str = instruction.get("context_type", "memory")
    level = instruction.get("level")
    skip_ia = instruction.get("skip_intent_analysis", False)
    typed_query_data = instruction.get("typed_query")
    filter_dsl = instruction.get("filter")
    priority = instruction.get("priority", 1)

    # 2. 构造 TypedQuery
    if typed_query_data:
        # 使用 MemRouter 预构造的 TypedQuery
        typed_query = TypedQuery(
            query=typed_query_data["query"],
            context_type=ContextType(typed_query_data.get("context_type", "memory")),
            intent=typed_query_data.get("intent", ""),
            priority=typed_query_data.get("priority", priority),
            target_directories=[target_uri] if target_uri else [],
        )
    else:
        # fallback: 从 instruction 通用字段构造
        typed_query = TypedQuery(
            query=query_text,
            context_type=ContextType(context_type_str) if context_type_str else None,
            intent=instruction.get("search_mode", ""),
            priority=priority,
            target_directories=[target_uri] if target_uri else [],
        )

    # 3. 权限检查
    real_ctx = self._ctx_or_default(ctx)
    if target_uri and target_uri not in {"/", "viking://"}:
        self._ensure_access(target_uri, ctx)

    # 4. 执行检索（统一走 retriever，无论是否跳过 intent analysis）
    storage = self._get_vector_store()
    embedder = self._get_embedder()
    retriever = HierarchicalRetriever(
        storage=storage,
        embedder=embedder,
        rerank_config=self.rerank_config,
        retrieval_config=self.retrieval_config,
    )

    result = await retriever.retrieve(
        typed_query,
        ctx=real_ctx,
        limit=instruction.get("limit", 10),
        score_threshold=instruction.get("score_threshold"),
        scope_dsl=filter_dsl,
        level=level,
    )

    # 5. 组装 FindResult（与 search/find 返回格式一致）
    memories, resources, skills = [], [], []
    for ctx_item in result.matched_contexts:
        if ctx_item.context_type == ContextType.MEMORY:
            memories.append(ctx_item)
        elif ctx_item.context_type == ContextType.RESOURCE:
            resources.append(ctx_item)
        elif ctx_item.context_type == ContextType.SKILL:
            skills.append(ctx_item)

    find_result = FindResult(
        memories=memories,
        resources=resources,
        skills=skills,
        query_plan=None,  # 跳过了 IntentAnalyzer，无 query_plan
    )
    return find_result

3.3 调用分支决策

MemRouter 输出 BackendQueryInstruction(backend_id="openviking_memory_backend", skip_intent_analysis=?, ...)
Dispatcher 判断 if instruction.skip_intent_analysis → 调用 VikingFS.execute_instruction()
else → 调用 VikingFS.search() 走正常 IntentAnalyzer 路径

3.4 三种调用路径对比

路径VLM tokens延迟适用场景
find()（原）0低无 session、target_uri 已知
search()（原）~3K-15K高有 session、需要意图分析
execute_instruction() 新增0低MemRouter 高置信命中，已明确 context_type/level/target_uri

四、query_spec 多后端路由设计

4.1 当前实现的局限

当前 TemplateQuerySpec 使用硬编码字段：

class TemplateQuerySpec(BaseModel):
    search_mode: str = "find"
    query_rewrite: Optional[str] = None
    openviking: Optional[OpenVikingQuerySpec] = None      # 硬编码
    graph: Optional[GraphQuerySpec] = None                # 硬编码

问题：新增第 4 个后端（如 episodic_memory_backend）时，必须修改 TemplateQuerySpec 和 query_instruction_builder.py 的 _assemble_instruction()。

推荐 4.2 可扩展方案：Adapter 自注册 Schema

Step 2: Adapter 自注册

# echomem/adapters/base.py

class MemoryBackendAdapter(ABC):
    @property
    @abstractmethod
    def backend_id(self) -> str: ...

    @property
    def spec_schema(self) -> Optional[type[BaseModel]]:
        """返回该后端 query_spec 的 Pydantic schema。
        None 表示使用原始 dict，不做强校验。"""
        return None

    def validate_spec(self, raw: Dict[str, Any]) -> Any:
        """校验并解析 backend_specs[backend_id] 的原始 dict。"""
        schema = self.spec_schema
        if schema is None:
            return raw
        return schema.model_validate(raw)

# echomem/adapters/openviking.py
class OpenVikingAdapter(MemoryBackendAdapter):
    @property
    def spec_schema(self) -> Optional[type[BaseModel]]:
        return OpenVikingQuerySpec  # Pydantic 自动校验

Step 4: QueryInstructionBuilder 改造

class QueryInstructionBuilder:
    def _assemble_instruction(
        self, route: RouteEntry, base_spec: TemplateQuerySpec, ...
    ) -> BackendQueryInstruction:
        instruction = BackendQueryInstruction(
            backend_id=route.backend_id,
            query=query_text,
            search_mode=base_spec.search_mode,
        )

        # 1. 先尝试硬编码字段（向后兼容）
        if route.backend_id == "openviking_memory_backend" and base_spec.openviking:
            self._apply_openviking(instruction, base_spec.openviking)
        elif route.backend_id == "graph_memory_backend" and base_spec.graph:
            self._apply_graph(instruction, base_spec.graph)
        elif route.backend_id == "temporal_memory_backend" and base_spec.temporal:
            self._apply_temporal(instruction, base_spec.temporal)

        # 2. 再尝试可扩展 backend_specs
        elif route.backend_id in base_spec.backend_specs:
            raw_spec = base_spec.backend_specs[route.backend_id]
            adapter = self._adapters.get(route.backend_id)
            if adapter and adapter.spec_schema:
                validated = adapter.validate_spec(raw_spec)
                instruction.extra_params.update(validated.model_dump())
            else:
                instruction.extra_params.update(raw_spec)

        return instruction

5.1 新增一个记忆后端的标准流程

步骤操作需要修改的文件
1在 MemoryBackendRegistry 注册新 backendpipeline 初始化代码 / 配置文件

六、端到端调用时序

场景：高置信 personal_fact_lookup（跳过 IntentAnalyzer）

① User"你还记得我喜欢什么颜色吗"
② MemRouterTemplateMatcher 命中 openviking.personal_fact_lookup.en.v2 (score=0.81)
③ RouteDecisionBranch 1 单后端接受 → openviking_memory_backend primary
④ QueryInstructionBuilder读取模板 query_spec → 生成 BackendQueryInstruction(skip_intent_analysis=true)
⑤ Dispatcher检测到 skip_intent_analysis=true → 调用 VikingFS.execute_instruction()
⑥ OpenViking直接构造 TypedQuery → HierarchicalRetriever.retrieve() （零 VLM token）
⑦ ResultFindResult → 返回给用户

场景：需要 session 上下文的 aggregation（不走跳过）

① User"我去年一共花了多少钱"
② MemRouter命中 openviking.aggregation_summary.v2 (score=0.75)
③ QueryInstructionBuilder生成 BackendQueryInstruction(skip_intent_analysis=false)
④ Dispatcher检测到 skip_intent_analysis=false → 调用 VikingFS.search(session_info=...)
⑤ OpenViking走 IntentAnalyzer.analyze() → 生成 QueryPlan → retriever （正常 VLM 路径）

场景：多后端同时命中（Graph + OpenViking）

① User"Jon 和 Gina 的关系以及 Jon 的偏好"
② MemRouterBranch 2: graph (primary, 0.72) + openviking (secondary, 0.69)
③ QueryInstructionBuilder生成 2 条指令：
① BackendQueryInstruction(backend_id="graph_memory_backend", search_mode="graph_traversal", extra_params={hop_depth:2})
② BackendQueryInstruction(backend_id="openviking_memory_backend", search_mode="find", skip_intent_analysis=true)
④ Dispatcher并行调用 GraphBackend.execute_instruction() + VikingFS.execute_instruction()
⑤ Merge合并两个后端的结果 → 去重 → 返回

9.2 新增后端的最小契约

新增后端只需满足以下三个契约：

  1. 后端注册：在 MemoryBackendRegistry 中声明 backend_id + backend_kind
  2. 模板声明：YAML 模板中通过 target.primary_backend_id 指向该后端，query_spec.backend_specs[<backend_id>] 声明查询参数
  3. Adapter 实现：继承 MemoryBackendAdapter，实现 backend_id、translate()，可选 spec_schema / get_default_spec / enrich_spec
