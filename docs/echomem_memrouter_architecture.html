EchoMem MemRouter v1.4 架构详解

面向 AI Agent 记忆检索场景的轻量级记忆后端路由器

一、项目概述

EchoMem MemRouter 是一个面向 AI Agent 记忆检索场景的轻量级记忆后端路由器。它只回答一个收敛的问题：

给定一条用户 query，应该把记忆检索请求路由到哪个记忆后端？

MemRouter 不决定后端内部的记忆类型、URI 路径、检索模式或 retrieval capability。这些决策由被选中的记忆后端或对应 adapter 自行完成。

当前 v1.4 范围：

  • 在 OpenViking、Graph、Temporal 三类逻辑后端之间进行路由
  • 主路径优先使用低成本的模板多原型 embedding 匹配
  • 当模板匹配低置信或处于灰区时，可启用 LLM 后备路由
  • 输出标准化的后端路由结果，并保留评测所需的 debug 元数据
  • 不执行真实记忆检索，真实检索由后续 backend adapter 承接

二、设计目标

设计目标 说明
只做后端路由 MemRouter 输出目标后端，不输出后端内部检索策略
低成本优先 模板多原型 embedding 匹配是主路径，LLM 只作为兜底
后端可扩展 新增记忆后端时注册 backend 和模板即可，不需要改 matcher 主算法
评测可观测 每轮评测记录模板命中率、LLM fallback 率、后端准确率、延迟和模板分数
Adapter 隔离 backend adapter 负责把 route result 翻译成后端自己的检索请求

四、Pipeline 各阶段详解

4.1 MemRouterPipeline — 主入口

核心类 MemRouterPipeline（pipeline.py）提供单一入口 route(query)，串联所有阶段。工厂方法 with_defaults() 自动装配 v1.4 默认配置：

pipeline = MemRouterPipeline.with_defaults(embedder)
result = pipeline.route("你记得我之前说过什么吗？")

默认注册的 3 个逻辑后端

backend_id backend_kind 路由范围 QueryContract
openviking_memory_backend openviking_native 个人语义记忆、profile、preferences、历史对话回忆、宽泛用户上下文 支持 entities, time_range
graph_memory_backend knowledge_graph 实体关系、关系遍历、多跳图问题、系统依赖关系 支持 entities, relation_hints
temporal_memory_backend temporal_store 时间线事实、持续时间比较、顺序推理、时间范围问题 支持 entities, time_range

4.2 Stage 1: QueryNormalizer — 查询归一化

轻量级文本归一化，不做分类、不做后端决策，仅标准化文本：

1. Strip 首尾空白
2. 标点符号替换为单个空格（CJK + ASCII）
3. 合并连续空白
4. 英文转小写（CJK 安全保留）

4.5 Stage 4: TemplateMatcher — 多原型向量匹配

核心打分算法，使用向量相似度将用户 query 与模板原型匹配。

正向打分公式

S_pos = 0.50 × S_max + 0.30 × S_mean@3 + 0.20 × S_centroid
  • S_max：最强单个 prototype 命中分数
  • S_mean@3：top 3 prototypes 的平均分，降低单条 prototype 偶然高分的影响
  • S_centroid：query 与模板整体语义中心（centroid）的相似度

Hard-Negative 惩罚

S_final = S_pos - lambda × max(0, delta_neg - M_neg)
  • M_neg：query 与 hard negative 的最大相似度差 = S_pos - S_neg
  • delta_neg：硬负例安全间隔阈值（模板配置）
  • lambda：惩罚系数（模板配置）

Backend 聚合

模板按分数排序后，聚合到 backend 级别：同一 backend 的多个模板只保留最高分，确保 top1/top2 代表不同后端。

Embedding 缓存

模板原型和硬负例的 embedding 在首次使用时计算并缓存（_proto_cache / _neg_cache），避免重复编码。

代码：echomem/matcher.py

4.6 Stage 5: RouteDecision — 三条分支决策

根据模板匹配分数和阈值，选择三条分支之一。默认后端为 openviking_memory_backend。

阈值参数（来自命中的最佳模板）

阈值 作用
accept 最低接受分数，best.score >= accept 才可能被接受
fallback 低于此分数直接进入 LLM fallback
margin top1 与 top2 的最小间隔，间隔不足视为模糊

Branch 1: 单后端接受 (template_embedding)

条件: best.score >= accept AND (second is None OR margin >= margin_thr)
输出: 1 个 primary route

Branch 2: 多后端接受 (template_embedding_multi_backend)

条件: best.score >= accept
      AND second.score >= second_accept
      AND best.backend != second.backend
      AND margin < margin_thr
输出: primary + secondary 两个 route
      + post_retrieval_requirements: {deduplicate_evidence, check_answerability}

Branch 3: LLM Fallback (llm_backend_fallback)

触发条件:
  - 无有效 backend 候选
  - best.score < fallback_thr
  - 模糊或间隔太小 (margin < margin_thr 且不满足多后端条件)

输出: 通过 LLMBackendRouter 决策，默认置信度 0.60

代码：echomem/decision.py

五、LLM 后备路由

5.1 设计原则

LLM fallback 是可选能力，适合在 benchmark 评测或模板覆盖仍不足的实验阶段启用。主路径始终是低成本的模板 embedding 匹配。

5.2 支持的 Provider

Provider 状态
mock 默认，用于单元测试，不发起真实请求
openai_compatible 已实现
anthropic_compatible 已实现
local_http 预留接口，尚未实现

5.3 闭集约束

LLM 只能从 MemoryBackendRegistry 中已注册且启用的 backend_id 列表中选择，不能自由发挥。

5.4 Fallback 信息记录

结果中 FallbackInfo 记录是否使用了 fallback、类型和原因，便于评测分析。

七、OpenViking Adapter

OpenVikingAdapter 是一个很薄的翻译层，遵循 MemoryBackendAdapter 抽象接口：

MemRouter 决定的内容

  • query 是否应该路由到 OpenViking
  • 路由置信度和命中的模板元数据
  • query hints（实体、时间提示、关系提示）

OpenViking 自行决定的内容

  • 检索哪个内部记忆路径
  • 使用 search、read、find、graph 或其他内部机制
  • 如何合并、排序、注入检索到的记忆

翻译输出示例

}

九、与 OpenViking 的关系

维度 EchoMem MemRouter OpenViking
职责边界 决定"哪个后端" 决定"后端内如何检索"
路由粒度 backend 级别（openviking / graph / temporal） 内部记忆路径级别（L0/L1/L2 + intent analysis）
主路径成本 本地 embedding 匹配（~毫秒级） 向量搜索 + 可选 rerank（~百毫秒级）
LLM 使用 fallback 才用（可选） intent analysis + memory extraction（频繁使用）
交互方式 输出 route result，由 adapter 翻译 接收 adapter 翻译后的参数执行检索

简言之：MemRouter 是 OpenViking 的"上游路由器"。当 Agent 收到用户 query 时，MemRouter 先判断这条 query 是关于个人记忆的（走 OpenViking）、实体关系的（走 Graph）、还是时间线的（走 Temporal），然后把 query 交给选中的后端自行处理。

十一、当前限制

  • Graph 和 Temporal 的真实 adapter 尚未实现（仅 OpenVikingAdapter 存在）
  • OpenVikingAdapter 当前只做参数翻译，不调用 OpenViking SDK/API
  • local_http LLM provider 已预留接口，但尚未实现
  • 模板覆盖仍在调优中，尤其是自然分布下的 OpenViking 个人记忆类 query
  • CJK 实体提取在 v1.4 MVP 中被禁用，避免过度提取常见短语
