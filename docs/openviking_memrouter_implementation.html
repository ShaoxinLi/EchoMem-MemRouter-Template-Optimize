OpenViking 侧 MemRouter 对接实现方案

OpenViking 需要新增哪些代码，才能消费 MemRouter 的 BackendQueryInstruction 并启用 fast path

一、背景与现状

EchoMem MemRouter v1.4 已经实现了完整的 Query Instruction 生成能力。当模板匹配高置信命中时，MemRouter 会输出包含 skip_intent_analysis=true 的 BackendQueryInstruction，OpenViking 可据此跳过自身的 VLM IntentAnalyzer（节省 3K-15K tokens）。

但当前 OpenViking 侧还没有实现消费这些指令的入口。 MemRouterVikingClient 在调用 execute_instruction() 时会因 AttributeError 自动降级为 find()，fast path 尚未真正跑通。

本方案定义 OpenViking 侧需要新增和修改的代码模块，使 fast path 端到端可用。

二、OpenViking 现有架构回顾

2.1 当前调用链路（baseline）

Agent / VikingBot
VikingClient.search(query)
VikingClient
AsyncHTTPClient.search(payload) → POST /v1/search
OpenViking Server
Session.search(query) → IntentAnalyzer.analyze(query) → VLM (~3K-15K tokens)
OpenViking Server
IntentResult → HierarchicalRetriever.retrieve(params) → 记忆结果

2.2 期望的 fast path 链路（MemRouter 增强后）

MemRouterVikingClient
MemRouter.route(query) → BackendQueryInstruction (skip_intent_analysis=true)
MemRouterVikingClient
AsyncHTTPClient.execute_instruction(instruction) → POST /v1/execute_instruction
OpenViking Server
InstructionExecutor.execute(instruction) → 跳过 IntentAnalyzer，0 VLM tokens
OpenViking Server
直接调用 HierarchicalRetriever.retrieve(params) → 记忆结果

三、需要新增/修改的模块清单

文件/模块 操作 说明
openviking/core/instruction_executor.py 新增 核心模块。解析 BackendQueryInstruction，直接调用 HierarchicalRetriever
openviking/api/routes.py 修改 新增 POST /v1/execute_instruction HTTP endpoint
openviking/client/async_http_client.py 修改 新增 execute_instruction(instruction) 方法
openviking/client/local_client.py 修改 同上（如果存在本地 client）
openviking/models/query_instruction.py 新增 Pydantic 模型：OpenVikingExecuteInstructionRequest / OpenVikingQueryResult
openviking/core/retriever.py 修改 确保 HierarchicalRetriever 支持按 instruction 参数直接检索（通常无需改）

四、详细实现

4.1 数据模型：openviking/models/query_instruction.py 新增

定义 OpenViking 侧接收和返回的数据结构。与 MemRouter 的 BackendQueryInstruction 对齐，但只包含 OpenViking 关心的字段。

"""OpenViking Query Instruction models — aligned with MemRouter BackendQueryInstruction."""

from __future__ import annotations

from typing import Any, Dict, List, Optional

from pydantic import BaseModel, Field


class TypedQueryTemplate(BaseModel):
    """Typed query template generated by MemRouter."""

    query: str
    context_type: str = "memory"
    intent: Optional[str] = None
    priority: int = 1
    entities: Optional[List[str]] = None


class OpenVikingExecuteInstructionRequest(BaseModel):
    """Request body for POST /v1/execute_instruction.

    Mirrors MemRouter's BackendQueryInstruction but is self-contained
    for OpenViking's API contract.
    """

    backend_id: str = Field(default="openviking_memory_backend")
    query: str
    search_mode: str = Field(default="find", pattern=r"^(find|search|read|graph)$")
    skip_intent_analysis: bool = True
    target_uri: Optional[str] = None
    context_type: Optional[str] = "memory"
    level: Optional[List[int]] = None
    limit: int = Field(default=10, ge=1, le=100)
    typed_query: Optional[TypedQueryTemplate] = None
    filter: Optional[Dict[str, Any]] = None
    # 保留扩展字段
    extra: Optional[Dict[str, Any]] = None

    class Config:
        extra = "allow"  # 允许 MemRouter 未来新增字段不报错


class MatchedContext(BaseModel):
    """Single matched memory context — same shape as existing OpenViking output."""

    uri: str
    context_type: str
    abstract: str
    overview: Optional[str] = None
    category: Optional[str] = None
    score: float = 0.0
    match_reason: Optional[str] = None
    relations: Optional[List[Dict[str, Any]]] = None


class OpenVikingQueryResult(BaseModel):
    """Response for execute_instruction — same shape as existing search/find result."""

    memories: List[MatchedContext] = Field(default_factory=list)
    resources: List[MatchedContext] = Field(default_factory=list)
    skills: List[MatchedContext] = Field(default_factory=list)
    total: int = 0
    query: str = ""
    target_uri: Optional[str] = None
    # Debug metadata for MemRouter observability
    _execution_meta: Optional[Dict[str, Any]] = Field(default=None, exclude=False)

    def set_meta(self, key: str, value: Any) -> None:
        if self._execution_meta is None:
            self._execution_meta = {}
        self._execution_meta[key] = value

4.2 核心执行器：openviking/core/instruction_executor.py 新增

InstructionExecutor 是 fast path 的核心。它接收 MemRouter 的指令，跳过 IntentAnalyzer，直接组装检索参数并调用 HierarchicalRetriever。

"""InstructionExecutor — execute BackendQueryInstruction without IntentAnalyzer.

This module provides the fast path for MemRouter-confident queries.
All logic that previously lived in IntentAnalyzer (target_uri selection,
level selection, search_mode selection) is now pre-computed by MemRouter
and passed directly via the instruction.
"""

from __future__ import annotations

import logging
from typing import TYPE_CHECKING, Any, Dict, List, Optional

from openviking.models.query_instruction import (
    MatchedContext,
    OpenVikingExecuteInstructionRequest,
    OpenVikingQueryResult,
)

if TYPE_CHECKING:
    from openviking.core.retriever import HierarchicalRetriever

logger = logging.getLogger(__name__)


class InstructionExecutor:
    """Execute a pre-computed instruction against the memory store.

    Design principles:
        - Zero VLM tokens: never calls IntentAnalyzer.
        - Reuse existing retriever: all storage access goes through
          HierarchicalRetriever so that caching, ACL, audit remain intact.
        - Fail-safe: if any required field is missing, raise a clear error
          so that MemRouterVikingClient can fallback to normal search().
    """

    def __init__(self, retriever: HierarchicalRetriever) -> None:
        self._retriever = retriever

    # ------------------------------------------------------------------ #
    # Public API
    # ------------------------------------------------------------------ #

    async def execute(
        self,
        request: OpenVikingExecuteInstructionRequest,
    ) -> OpenVikingQueryResult:
        """Execute the instruction and return matched contexts.

        Args:
            request: The instruction produced by MemRouter.

        Returns:
            OpenVikingQueryResult containing memories/resources/skills.

        Raises:
            ValueError: If the instruction contains unsupported parameters
                or missing required fields, signaling MemRouter to fallback.
        """
        logger.info(
            "InstructionExecutor: query='%s' mode=%s uri=%s level=%s",
            request.query,
            request.search_mode,
            request.target_uri,
            request.level,
        )

        # Validate minimum required fields
        if not request.query:
            raise ValueError("Instruction 'query' is empty")

        # Build retriever parameters from the instruction
        retrieve_params = self._build_retrieve_params(request)

        # Dispatch by search_mode
        if request.search_mode == "find":
            raw_results = await self._retriever.find(**retrieve_params)
        elif request.search_mode == "search":
            raw_results = await self._retriever.search(**retrieve_params)
        elif request.search_mode == "read":
            raw_results = await self._retriever.read(**retrieve_params)
        elif request.search_mode == "graph":
            raw_results = await self._retriever.graph_query(**retrieve_params)
        else:
            raise ValueError(f"Unsupported search_mode: {request.search_mode}")

        # Convert raw retriever output to standardized result
        result = self._convert_to_result(raw_results, request)

        # Attach execution metadata for MemRouter observability
        result.set_meta("executor", "InstructionExecutor")
        result.set_meta("skip_intent_analysis", True)
        result.set_meta("search_mode", request.search_mode)

        logger.info(
            "InstructionExecutor: returned %d memories, %d resources, %d skills",
            len(result.memories),
            len(result.resources),
            len(result.skills),
        )
        return result

    # ------------------------------------------------------------------ #
    # Internal helpers
    # ------------------------------------------------------------------ #

    def _build_retrieve_params(
        self,
        request: OpenVikingExecuteInstructionRequest,
    ) -> Dict[str, Any]:
        """Map instruction fields to HierarchicalRetriever parameters.

        The retriever likely accepts:
            - query: str
            - target_uri: str (optional)
            - context_type: str (optional)
            - level: list[int] (optional)
            - limit: int
            - filter: dict (optional)
            - typed_query: dict (optional, for tracing/debug)
        """
        params: Dict[str, Any] = {
            "query": request.query,
            "limit": request.limit,
        }

        if request.target_uri:
            params["target_uri"] = request.target_uri

        if request.context_type:
            params["context_type"] = request.context_type

        if request.level is not None:
            params["level"] = request.level

        if request.filter:
            params["filter"] = request.filter

        # typed_query 主要供 tracing / debug 使用，retriever 不直接消费
        if request.typed_query:
            params["typed_query"] = request.typed_query.model_dump()

        # Merge any extra params MemRouter may have sent
        if request.extra:
            for k, v in request.extra.items():
                if k not in params:
                    params[k] = v

        return params

    def _convert_to_result(
        self,
        raw_results: Any,
        request: OpenVikingExecuteInstructionRequest,
    ) -> OpenVikingQueryResult:
        """Convert retriever-native output to OpenVikingQueryResult.

        This is a thin adapter layer. If HierarchicalRetriever already returns
        objects with the same shape, we can pass them through directly.
        """
        # Handle dict output (most common)
        if isinstance(raw_results, dict):
            return OpenVikingQueryResult(
                memories=[
                    MatchedContext(**m) if isinstance(m, dict) else m
                    for m in raw_results.get("memories", [])
                ],
                resources=[
                    MatchedContext(**r) if isinstance(r, dict) else r
                    for r in raw_results.get("resources", [])
                ],
                skills=[
                    MatchedContext(**s) if isinstance(s, dict) else s
                    for s in raw_results.get("skills", [])
                ],
                total=raw_results.get("total", 0),
                query=request.query,
                target_uri=request.target_uri,
            )

        # Handle list output (direct list of MatchedContext)
        if isinstance(raw_results, list):
            contexts = [
                MatchedContext(**item) if isinstance(item, dict) else item
                for item in raw_results
            ]
            return OpenVikingQueryResult(
                memories=contexts,
                total=len(contexts),
                query=request.query,
                target_uri=request.target_uri,
            )

        # Handle already-modeled output
        if isinstance(raw_results, OpenVikingQueryResult):
            return raw_results

        # Fallback — try to coerce from object attributes
        return OpenVikingQueryResult(
            memories=[
                MatchedContext(**m) if isinstance(m, dict) else m
                for m in getattr(raw_results, "memories", [])
            ],
            resources=[
                MatchedContext(**r) if isinstance(r, dict) else r
                for r in getattr(raw_results, "resources", [])
            ],
            skills=[
                MatchedContext(**s) if isinstance(s, dict) else s
                for s in getattr(raw_results, "skills", [])
            ],
            total=getattr(raw_results, "total", 0),
            query=request.query,
            target_uri=request.target_uri,
        )

4.3 HTTP API 端点：openviking/api/routes.py 修改

在现有 FastAPI/HTTP router 中新增 POST /v1/execute_instruction endpoint。

"""Add execute_instruction endpoint to existing OpenViking API routes."""

from fastapi import APIRouter, HTTPException

from openviking.core.instruction_executor import InstructionExecutor
from openviking.core.retriever import HierarchicalRetriever
from openviking.models.query_instruction import (
    OpenVikingExecuteInstructionRequest,
    OpenVikingQueryResult,
)

router = APIRouter()

# Existing routes ...
# @router.post("/v1/search")
# async def search(...)


@router.post("/v1/execute_instruction", response_model=OpenVikingQueryResult)
async def execute_instruction(
    request: OpenVikingExecuteInstructionRequest,
) -> OpenVikingQueryResult:
    """Execute a pre-computed memory query instruction (MemRouter fast path).

    This endpoint bypasses IntentAnalyzer entirely. The caller (MemRouter)
    is responsible for having already determined:
        - target_uri
        - search_mode (find / search / read / graph)
        - level (which hierarchy levels to query)
        - context_type

    Args:
        request: The instruction payload from MemRouter.

    Returns:
        OpenVikingQueryResult with memories, resources, skills.

    Raises:
        HTTPException 400: If the instruction is invalid or unsupported.
        HTTPException 500: If retriever fails internally.
    """
    # Obtain the global retriever instance (however your app manages it)
    retriever = HierarchicalRetriever.get_instance()
    executor = InstructionExecutor(retriever)

    try:
        result = await executor.execute(request)
    except ValueError as exc:
        raise HTTPException(status_code=400, detail=str(exc)) from exc
    except Exception as exc:
        logger.exception("InstructionExecutor failed")
        raise HTTPException(status_code=500, detail="Internal retriever error") from exc

    return result

4.4 客户端 SDK：openviking/client/async_http_client.py 修改

在 AsyncHTTPClient 中新增 execute_instruction() 方法，使 MemRouterVikingClient 可以直接调用。

"""Add execute_instruction to AsyncHTTPClient."""

from typing import Any, Dict

import httpx


class AsyncHTTPClient:
    """Async HTTP client for OpenViking API."""

    def __init__(self, base_url: str, api_key: Optional[str] = None) -> None:
        self.base_url = base_url.rstrip("/")
        self.api_key = api_key
        self._client = httpx.AsyncClient(
            base_url=self.base_url,
            headers={"Authorization": f"Bearer {api_key}"} if api_key else {},
            timeout=30.0,
        )

    # ------------------------------------------------------------------ #
    # Existing methods (search, find, commit, etc.)
    # ------------------------------------------------------------------ #

    async def search(self, query: str, **kwargs: Any) -> Dict[str, Any]:
        payload = {"query": query, **kwargs}
        resp = await self._client.post("/v1/search", json=payload)
        resp.raise_for_status()
        return resp.json()

    async def find(self, query: str, target_uri: str = "", **kwargs: Any) -> Dict[str, Any]:
        payload = {"query": query, "target_uri": target_uri, **kwargs}
        resp = await self._client.post("/v1/find", json=payload)
        resp.raise_for_status()
        return resp.json()

    # ... other existing methods ...

    # ------------------------------------------------------------------ #
    # NEW: execute_instruction for MemRouter fast path
    # ------------------------------------------------------------------ #

    async def execute_instruction(self, instruction: Dict[str, Any]) -> Dict[str, Any]:
        """Execute a pre-computed BackendQueryInstruction (MemRouter fast path).

        Args:
            instruction: Dictionary conforming to OpenVikingExecuteInstructionRequest.
                Expected keys:
                    - query: str
                    - search_mode: str  ("find" | "search" | "read" | "graph")
                    - skip_intent_analysis: bool
                    - target_uri: Optional[str]
                    - context_type: Optional[str]
                    - level: Optional[List[int]]
                    - limit: int
                    - typed_query: Optional[dict]
                    - filter: Optional[dict]

        Returns:
            Dictionary with "memories", "resources", "skills", "total", etc.

        Raises:
            httpx.HTTPStatusError: If server returns 4xx/5xx.
        """
        resp = await self._client.post("/v1/execute_instruction", json=instruction)
        resp.raise_for_status()
        return resp.json()

五、与现有架构的边界

5.1 不改动的模块（保持原样）

模块 不改动的理由
IntentAnalyzer Fast path 直接绕过它；normal path 继续正常使用
HierarchicalRetriever 核心逻辑 InstructionExecutor 只是它的调用方，不修改内部实现
Session 管理 execute_instruction 是无状态的，不依赖 session 上下文
commit / write 链路 MemRouter 是只读路由层，不拦截写入

5.2 新增的边界

+------------------+        +---------------------+        +------------------+
|  MemRouter       |        |  OpenViking         |        |  Storage         |
|  (EchoMem)       |        |  (this doc)         |        |  (unchanged)     |
+------------------+        +---------------------+        +------------------+
| BackendQuery     |  -->  | InstructionExecutor |  -->  | Hierarchical     |
| Instruction      |  HTTP  | .execute(request)   |  call  | Retriever        |
+------------------+        +---------------------+        +------------------+
                                      |
                                      v
                              IntentAnalyzer (bypassed in fast path)

七、向后兼容策略

7.1 兼容性矩阵

场景 MemRouter 版本 OpenViking 版本 行为
旧 Agent + 旧 OpenViking 未使用 无 execute_instruction 原生 VikingClient.search()，无变化
新 Agent + 旧 OpenViking v1.4+ 无 execute_instruction MemRouterVikingClient 捕获 AttributeError，自动降级为 find()。IntentAnalyzer 仍运行。
新 Agent + 新 OpenViking v1.4+ 有 execute_instruction Fast path 生效。skip_intent_analysis=true 时 0 VLM tokens。
旧 Agent + 新 OpenViking 未使用 有 execute_instruction Agent 不调用 MemRouter，OpenViking 新接口不触发。无变化。

7.2 渐进式上线建议

  1. Phase 1 — 接口就绪： 在 OpenViking 侧部署 execute_instruction endpoint，但不对外暴露。仅用于内部测试。
  2. Phase 2 — 灰度验证： 让 MemRouterVikingClient 调用 execute_instruction，对比 fast path 和 normal path 的结果一致性。确认召回率、排序、格式无差异。
  3. Phase 3 — 全量启用： 确认无问题后，正式将 MemRouterVikingClient 作为 VikingClient 的默认包装层。
  4. Phase 4 — 模板扩覆盖： 随着模板覆盖更多 intent family，逐步扩大 skip_intent_analysis=true 的场景范围。

十、总结

MemRouter 侧已经准备就绪。OpenViking 侧只需完成三件事即可启用 fast path：

  1. 新增 InstructionExecutor：解析 BackendQueryInstruction，直接调用 HierarchicalRetriever，跳过 IntentAnalyzer。
  2. 新增 HTTP endpoint POST /v1/execute_instruction：接收 instruction，返回检索结果。
  3. 在 AsyncHTTPClient 中暴露 execute_instruction()：让 MemRouterVikingClient 可以一行调用。

整个修改是纯新增 + 薄封装，不改动现有 IntentAnalyzer、Session、Retriever 核心逻辑，具备完整的向后兼容性。即使 OpenViking 未升级，MemRouterVikingClient 也会自动降级到 find()，不会破坏现有功能。
