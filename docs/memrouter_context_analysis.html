MemRouter 上下文感知能力分析

记忆模板匹配未考虑 Agent 历史上下文对精度的影响评估

核心问题

MemRouter 的记忆模板匹配方案没有考虑 Agent 上下文中的历史信息和对话内容，而 OpenViking 记忆召回的意图识别输入包含了 session 压缩摘要 + 最近 5 条消息。这个差异是否会影响路由精度？

一、两者的上下文差异

维度 MemRouter 模板匹配 OpenViking IntentAnalyzer
输入 当前 query + 弱正则 hints session 压缩摘要 + 最近 5 条消息 + 当前 query
决策粒度 后端级别（选哪个记忆库） 内部检索策略（选哪种 context_type + target_uri）
上下文敏感度 无 高

二、会影响精度的典型场景

场景 1：指代消解型 Query（影响最大）

Round 1: "我的生日是 1990 年 5 月 20 日"
        → MemRouter 路由到 OpenViking ✓

Round 2: "你还记得吗？"
        → MemRouter 匹配"回忆"模板 → OpenViking ✓
          但无法知道是"生日"这个事实

Round 3: "那是什么星座？"
        → MemRouter 只看到"星座"
          → 可能误路由到 Graph（实体知识）
          → 而非 OpenViking（个人记忆）

OpenViking 有上下文：看到 Round 1 提到生日 → 知道问的是"我的生日星座" → 正确检索个人记忆。

场景 2：省略主语的 Query

User: "把它改成红色"

MemRouter：看到"改成"（操作动词）
          → 可能路由到 skill 执行层

OpenViking（有上下文）：看到上文讨论的是"用户头像"
                      → 知道是修改头像颜色
                      → 路由到 memory 查询用户偏好

场景 3：意图漂移场景（影响较小）

Round 1: "北京到上海的高铁经过哪些城市？"
        → Graph（地理关系）

Round 2: "那到上海要多长时间？"
        → MemRouter 看到"多长时间" → Temporal ✓
          但如果有上下文，可能更确定是接续 Round 1 的 travel query

三、MemRouter 的缓解机制

MemRouter 虽然不考虑上下文，但有以下设计来缓解精度损失：

1. 默认兜底为 OpenViking

DEFAULT_BACKEND_ID = "openviking_memory_backend"

模糊 query 大概率路由到个人记忆后端，这对 Agent 场景通常是合理的。

2. 路由粒度粗（只选后端，不选内部策略）

即使不知道具体"记住什么"，只要知道是 memory 类 query 就够了。具体检索什么由 OpenViking 内部的 IntentAnalyzer 在有了上下文后决定。

3. 多 backend 输出（Branch 2）

当 top1/top2 间隔不足时，同时输出两个后端（primary + secondary），让下游合并检索结果。

四、结论

场景 MemRouter 精度影响 严重程度
当前 query 自包含完整语义 无影响 -
需要指代消解（"它"、"那个"） 可能路由正确后端但参数不足 中等
意图高度依赖上文（"还有呢？"） 可能误判后端 较高
常见个人记忆/事实查询 无影响，模板覆盖度高 -

核心权衡

MemRouter 牺牲了一部分上下文敏感精度，换取了：

  • 零 LLM token 成本（本地 embedding 匹配）
  • 毫秒级延迟

对于"选后端"这个粗粒度任务，当前 query 通常已包含足够信息；真正的上下文理解（指代消解、意图细化）留给了 OpenViking 的 IntentAnalyzer 在后端内部处理。

潜在优化方向

如果要提升 MemRouter 的上下文感知能力，可以在 MemoryRouteRequest 中增加 session_context 字段，让 QueryFeatureBuilder 在特征提取时考虑历史消息。但这会打破"轻量级"的设计原则，需要权衡。
