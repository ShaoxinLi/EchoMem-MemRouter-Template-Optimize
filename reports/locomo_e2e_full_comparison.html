回答准确率下降根因分析 (44.37% vs 基线 60.72%)
⚠️
回答准确率下降 16.35pp，主因是 DeepSeek 服务不稳定 + Fast Path 质量低于 Native Search
两次实验使用相同的 OpenViking 数据和几乎相同的 MemRouter 代码。Backend 准确率从 36.36% 提升至 64.31%，证明路由逻辑在改进；但答案准确率反而大幅下降，说明瓶颈已从「路由」转移到「下游执行质量」。
1. DeepSeek API 服务不稳定（最大因素）
  • 当前 run VikingBot gateway 日志有 29 条 DeepSeek "Internal Server Error"（基线 0 条）
  • MemRouter LLM fallback 出现 66 次 DeepSeek 错误/超时（基线 0 次）
  • 966/967 个同路由同 backend 的问题产生了不同答案，说明即使请求未 outright 失败，DeepSeek 输出质量也存在显著波动
  • VikingBot answer generation 依赖 DeepSeek（agents.model = deepseek-v4-flash），服务负载高时幻觉和遗漏增加
2. Fast Path 质量低于 Native Search
  • Template hit 触发 fast path（skip_intent_analysis=True），绕过 OpenViking IntentAnalyzer
  • 当前 run template hit 率更高（53.90% vs 45.39%），更多查询跳过了 IntentAnalyzer
  • Template-hit 准确率 42.11% 低于非 template-hit 的 47.01%
  • 即使是「基线也是 template hit、当前也是 template hit」的同一批问题，准确率也从 51.94% 降至 41.67%
补充数据：当前 run 有 39 个空/极短回答 + 19 个 error 回答，基线仅 6 + 1。Fix2 降低阈值后，约 74 个原走 LLM fallback + Native Search 的问题被改判为 template hit + Fast Path，执行路径的改变也贡献了部分下降。
结论：Backend 准确率 36% → 64% 证明 MemRouter 路由在真实改进。但答案准确率现在受限于下游执行质量而非路由正确性。两个最大杠杆：① 在 DeepSeek 服务稳定时段重跑，预期可恢复大部分损失的 16pp；② 优化 Fast Path（仅高置信度匹配才跳过 IntentAnalyzer，或为 Fast Path 补充轻量级 intent 解析）。

改进路线与待办
已达成 (Fix2)
  • temporal 阈值下调 (0.50→0.40)，新增 25+ 原型
  • graph 阈值下调 (0.60→0.50)，新增 10+ 原型
  • LLM fallback prompt 增加 TEMPORAL-OVERRIDE RULE
  • v2 标签口径修正，消除 graph 过标
  • Template hit rate +8.5pp，Fallback rate -12.8pp
待优化
  • Temporal↔OV 边界：约 180 题 temporal 错判为 OV，需进一步收紧 OV 模板 hard negatives
  • Graph 准确率：仅 22.92%，需提升 entity_relation 语义区分度
  • Category 2：38.01% 仍为短板，时序推理是核心难点
  • 回答质量（Fast Path）：template-hit 准确率 (42.11%) 低于非 template-hit (47.01%)。Fast Path 绕过 IntentAnalyzer 导致召回质量下降。需：① 仅高置信度匹配才走 fast path；② 为 fast path 补充轻量级 intent 解析
  • 回答质量（DeepSeek 稳定性）：当前 run 受 DeepSeek 服务不稳定影响显著（29 次 gateway error + 66 次 routing error）。需在服务稳定时段重跑以排除 API 波动干扰
  • 基础设施：66 题 DeepSeek 超时/错误，需增加重试或降级
